# Custom pattern secret scanning untuk API key KopiKita (contoh jawaban Lab L1.3)

Format API key internal KopiKita tidak dikenal pola bawaan GitHub, jadi perlu custom pattern.
Strukturnya mengikuti contoh custom pattern di Modul 02 repo paulasilvatech/Secure-Code-AI-Dev.

Buat di **Settings → Advanced Security → Secret scanning → Custom patterns → New pattern**:

| Kolom | Nilai |
| --- | --- |
| Pattern name | KopiKita API key |
| Secret format | `kopikita_(live\|test)_[a-f0-9]{32}` |
| Before secret (opsional) | `\A\|[^0-9A-Za-z]` |
| After secret (opsional) | `\z\|[^0-9A-Za-z]` |
| Test string | `PAYMENT_API_KEY = "kopikita_live_0123456789abcdef0123456789abcdef"` |

Langkah:

1. Klik **Save and dry run** dan pastikan contoh di test string cocok.
2. Klik **Publish pattern**. GitHub memindai ulang seluruh histori repo.
3. Aktifkan **push protection** untuk pattern ini agar key baru ditolak saat push.

Hasil yang diharapkan di tab **Security → Secret scanning** (filter: custom patterns),
dua alert untuk `api/config.py`:

| Secret | Lokasi | Keterangan |
| --- | --- | --- |
| `kopikita_live_7c2e…0e56` | `api/config.py` di branch start (dan histori) | Key aktif yang tertanam di kode |
| `kopikita_live_0011…ddee` | hanya histori, commit "Tambah integrasi gateway pembayaran" | Rahasia palsu di histori: sudah tidak ada di kode, tetapi tetap bocor |

Alert kedua adalah inti latihan: menghapus key dari kode tidak menghapusnya dari histori.
Keduanya ditutup dengan status **Revoked** setelah runbook dijalankan.
