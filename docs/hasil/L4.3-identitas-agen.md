# Identitas agen dan kredensial cloud (contoh jawaban Lab L4.3)

## 1. Secret cloud statis → OIDC

Sebelum (warisan L3.2): `deploy.yml` membaca `AWS_ACCESS_KEY_ID` dan `AWS_SECRET_ACCESS_KEY`
dari secret repo. Kunci itu berumur panjang; bocor sekali, bisa dipakai di mana saja.

Sesudah: `deploy.yml` meminta token OIDC (`id-token: write` hanya di job `deploy`) dan
`aws-actions/configure-aws-credentials` menukarnya dengan kredensial sementara.

Trust policy role di AWS (dibuat admin cloud, bukan oleh agen). Kuncinya klaim `sub`
dibatasi ke repo **dan** branch, bukan wildcard `repo:ORG/*`:

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Federated": "arn:aws:iam::<AKUN>:oidc-provider/token.actions.githubusercontent.com"},
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {
        "token.actions.githubusercontent.com:aud": "sts.amazonaws.com",
        "token.actions.githubusercontent.com:sub": "repo:<ORG>/kopikita-vuln:ref:refs/heads/main"
      }
    }
  }]
}
```

Simpan ARN role di **variable** repo `AWS_DEPLOY_ROLE_ARN` (bukan secret: ARN bukan rahasia).
Setelah OIDC jalan, hapus secret `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` dan cabut kuncinya di IAM.

## 2. Agen punya identitas sendiri

| Agen | Identitas | Hak | Tidak boleh |
| --- | --- | --- | --- |
| Review PR (`security-review.yml`) | `GITHUB_TOKEN` job | `contents: read`, `pull-requests: write` | push, merge |
| Digest (`security-digest.yml`) | `GITHUB_TOKEN` job | `issues: write`, `security-events: read` | menulis kode |
| Agen triase (L3.1, laptop/CI) | fine-grained PAT atau GitHub App khusus agen, hanya repo ini | Contents: read & write, Pull requests: read & write | Administration, merge (ditahan ruleset), Secrets |

Jangan memakai PAT pribadi developer untuk agen: jejak audit bercampur dan haknya terlalu luas.
Beri nama yang jelas (mis. `kopikita-agen-triase`) dan masa berlaku pendek (≤ 30 hari).

## 3. PR buatan agen wajib label + reviewer manusia

- `agent-pr-gate.yml` (job `label-agen`) gagal bila PR dari branch `fix/*` / `claude/*`
  atau dari akun Bot tidak berlabel `ai-generated`.
- Ruleset `main-dilindungi` (terapkan: `scripts/terapkan-ruleset.sh OWNER/kopikita-vuln`):
  1 approval, review code owner, approval ulang setelah push terakhir, status check wajib
  `label-agen` dan `scan` (hidden-chars).
- Template PR punya checklist "Dibantu/ditulis agen AI".

Ringkasan PR yang meyakinkan dari agen **bukan** review. Reviewer manusia membaca diff.
