## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Memperbaiki tiga alert CodeQL dari catatan triase L1.2 dengan bantuan Claude, lalu membuktikan perbaikannya.

1. Berikan alert CodeQL (CWE, berkas, jalur data) ke Claude di plan mode.
2. Setujui rencana; minta patch beserta test negatif.
3. Jalankan /claude-security → Suggest patches; git apply, satu PR per patch.
4. Tunggu CodeQL: alert harus tertutup oleh PR tersebut.

**Jebakan umum.** Claude menghapus atau melemahkan test agar hijau. Periksa setiap perubahan pada folder tests/.

## Persiapan

- Catatan triase L1.2 (`docs/hasil/L1.2-triase.md`) sudah ada di branch start.
- Jadikan `lab/L2.3-start` default branch, lalu Actions → CodeQL → **Run workflow** pada branch itu
  agar alert 1–3 tercatat untuk branch ini (filter Security: `branch:lab/L2.3-start`).
- Plugin Claude Security: di sesi Claude, `/plugin install claude-security@claude-plugins-official`.

```bash
git switch lab/L2.3-start && git switch -c kerja/L2.3
```

## Langkah rinci

### Langkah 1 · Berikan alert CodeQL (CWE, berkas, jalur data) ke Claude di plan mode.

Mulai Claude di **plan mode** dan beri data alert, bukan sekadar "perbaiki keamanan":

```text
> Perbaiki alert CodeQL berikut. Satu alert per patch.
  Alert 1: py/sql-injection (CWE-89), api/app.py fungsi login.
    Source: request.get_json() -> username. Sink: cur.execute(query) (query disusun string).
  Alert 2: py/path-injection (CWE-22), api/app.py fungsi invoice.
    Source: request.args.get("file"). Sink: open(path).
  Alert 3: py/flask-debug (CWE-215/489), api/app.py blok __main__: app.run(debug=True).
  Ikuti CLAUDE.md. Untuk tiap alert: rencana patch minimal + test negatif yang gagal sebelum patch.
```

### Langkah 2 · Setujui rencana; minta patch beserta test negatif.

Baca rencananya. Yang diharapkan:

- **Alert 1**: query berparameter `WHERE username = ? AND password_hash = ?`.
- **Alert 2**: hanya nama berkas polos `invoice-<angka>.txt` (regex `invoice-\d+\.txt`), lalu
  `realpath` + `commonpath` memastikan path tetap di `INVOICE_DIR`; selain itu 400/404.
- **Alert 3**: `app.run(host="127.0.0.1", port=5000)` tanpa `debug=True`.

Setujui, lalu minta patch **beserta test negatif** di `tests/test_remediasi_l2_3.py`:
injeksi `alice' OR '1'='1' --` harus 401; `../config.py`, `..%2fconfig.py`, `/etc/passwd`
harus 400/404; login dan invoice yang sah tetap berhasil.

Periksa setiap perubahan di `tests/` sebelum menerima (jebakan slide).

### Langkah 3 · Jalankan /claude-security → Suggest patches; git apply, satu PR per patch.

Bandingkan dengan Claude Security, lalu ubah menjadi PR terpisah per patch:

```text
/claude-security
```

Pilih **Scan codebase** (folder `api/`), tunggu hasil, lalu **Suggest patches**. Plugin menulis
berkas patch; terapkan satu per satu di branch sendiri:

```bash
git switch -c fix/sql-login lab/L2.3-start
git apply <berkas-patch-alert-1>.patch      # atau patch hasil plan mode langkah 2
python -m pytest -q
git commit -am "fix: query berparameter di login (alert 1)"
git push -u origin fix/sql-login && gh pr create --base lab/L2.3-start --fill
```

Ulangi untuk `fix/path-invoice` (alert 2) dan `fix/flask-debug` (alert 3).
Alert 4 (password di log) **tidak** dikerjakan di sini: itu tugas agen triase di Lab L3.1.

### Langkah 4 · Tunggu CodeQL: alert harus tertutup oleh PR tersebut.

Di setiap PR, check **CodeQL** melaporkan alert yang diperbaiki. Merge PR satu per satu; push ke
`lab/L2.3-start` memicu analisis ulang dan alert berpindah ke status **Closed (Fixed)**.

Bandingkan patch Claude dengan saran perbaikan di halaman alert CodeQL (bagian *Recommendation*).

## Bukti selesai

- Tiga PR terpisah (satu per alert), masing-masing berisi patch + test negatif.
- Security → Code scanning, filter `branch:lab/L2.3-start is:closed`: alert 1–3 berstatus Fixed.
- `pytest -q` lulus; tidak ada test lama yang dihapus atau dilemahkan (`git diff lab/L2.3-start -- tests/`
  hanya menambah).
