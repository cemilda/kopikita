## Dari slide

**Tujuan.** Menangani alert Dependabot dan memasang gerbang yang menolak dependensi rentan baru di PR.

1. Tambahkan .github/dependabot.yml untuk pip, npm, dan github-actions.
2. Urutkan alert: KEV dulu, lalu severity + EPSS; merge satu PR security update.
3. Pasang dependency-review-action (fail-on-severity: high); uji dengan versi lama.
4. Verifikasi satu saran paket dari AI di registry: umur, unduhan, maintainer.

**Jebakan umum.** Menaikkan versi mayor tanpa menjalankan test; perbaikan keamanan menjadi bug fungsional.

## Langkah rinci

### Langkah 1 · Tambahkan .github/dependabot.yml untuk pip, npm, dan github-actions.

Buat `.github/dependabot.yml` dengan tiga ekosistem (format mengikuti contoh Modul 02 repo
Secure-Code-AI-Dev):

```yaml
version: 2
updates:
  - package-ecosystem: "pip"
    directory: "/api"
    schedule: {interval: "weekly"}
  - package-ecosystem: "npm"
    directory: "/web"
    schedule: {interval: "weekly"}
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule: {interval: "weekly"}
```

`directory` menunjuk folder yang berisi manifest (`/api` untuk `requirements.txt`, `/web` untuk
`package.json`). Ekosistem `github-actions` membuat Dependabot ikut memperbarui versi action,
termasuk action yang nanti dipin ke SHA di Lab L3.2.

### Langkah 2 · Urutkan alert: KEV dulu, lalu severity + EPSS; merge satu PR security update.

Ekspor alert lalu urutkan dengan skrip (angka dihitung kode, bukan ditebak):

```bash
gh api "repos/{owner}/{repo}/dependabot/alerts?state=open&per_page=100" > dependabot.json
python scripts/prioritize_alerts.py --alerts dependabot.json --online
```

Urutan skrip: **KEV dulu** (sudah dieksploitasi), lalu **severity**, lalu **EPSS**
(peluang dieksploitasi 30 hari ke depan). Tanpa internet, pakai fixture:
`--alerts tests/fixtures/dependabot-alerts.json --kev tests/fixtures/kev.json --epss tests/fixtures/epss.json`.

Merge satu PR security update: Security → Dependabot → pilih alert `requests` →
**Create Dependabot security update**. Tunggu CI, jalankan `pytest -q` secara lokal pada branch
PR itu, baru merge. (Alternatif manual: ubah `requests==2.25.1` menjadi `requests==2.32.4`.)

### Langkah 3 · Pasang dependency-review-action (fail-on-severity: high); uji dengan versi lama.

Tambahkan `.github/workflows/dependency-review.yml`:

```yaml
on: pull_request
permissions: {contents: read}
jobs:
  dependency-review:
    runs-on: ubuntu-latest
    permissions: {contents: read, pull-requests: write}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/dependency-review-action@v5.0.0
        with:
          fail-on-severity: high
          comment-summary-in-pr: on-failure
```

Merge ke `lab/L1.4-start`, lalu uji dengan versi lama yang punya advisory high:

```bash
git switch -c uji/dependensi-lama lab/L1.4-start
echo "urllib3==1.26.4" >> api/requirements.txt
git commit -am "uji: dependensi lama" && git push -u origin uji/dependensi-lama
gh pr create --base lab/L1.4-start --fill
```

Check **Dependency review** harus **gagal** dan komentar ringkasan muncul di PR. Tutup PR tanpa merge.
Jalan pintas: branch siap pakai `aux/L1.4-pr-dependensi-lama` (induknya `lab/L1.4-solution`).

### Langkah 4 · Verifikasi satu saran paket dari AI di registry: umur, unduhan, maintainer.

Minta Claude atau asisten lain menyarankan paket untuk satu kebutuhan (mis. "library Python untuk
validasi nomor telepon Indonesia"). Sebelum `pip install`, periksa di registry dan isi tabel di
`docs/hasil/L1.4-cek-paket-ai.md`:

| Pemeriksaan | Cara |
| --- | --- |
| Paket ada | `https://pypi.org/project/<nama>/` (404 = halusinasi) |
| Umur | tanggal rilis pertama di *Release history* |
| Unduhan | `https://pypistats.org/packages/<nama>` |
| Maintainer | bagian *Maintainers* dan repo sumbernya |
| Kesehatan repo | OpenSSF Scorecard: `https://scorecard.dev/viewer/?uri=github.com/<org>/<repo>` |

- Satu PR security update di-merge dengan CI dan `pytest -q` hijau.
- PR uji `urllib3==1.26.4` gagal di check **Dependency review**.
