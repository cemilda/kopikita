## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Menemukan kerentanan otorisasi (BOLA) di aplikasi lab yang berjalan, lalu memperbaikinya bersama Claude dengan test regresi.

1. Jalankan aplikasi lab; siapkan dua akun uji (pelanggan A dan B).
2. Pindai dengan HawkScan (dua profil) atau ZAP (token login) memakai openapi.yaml.
3. Berikan temuan + cURL ke Claude; minta telusuri baris penyebab dan patch.
4. Tambahkan test: B tidak boleh membaca pesanan A; pindai ulang sampai bersih.

**Jebakan umum.** Memindai tanpa login sehingga endpoint di balik autentikasi tidak pernah diuji.

## Persiapan

- Jalur ZAP (tanpa akun) memakai Docker; jalur StackHawk butuh akun gratis, `HAWK_API_KEY`, dan
  `HAWK_APP_ID` (buat aplikasi di dashboard StackHawk).
- Akun uji bawaan database lab: **pelanggan A** `alice` / `alice123` (pesanan 101, 103) dan
  **pelanggan B** `budi` / `budi123` (pesanan 102).
- Hanya pindai aplikasi yang Anda jalankan sendiri.

## Langkah rinci

### Langkah 1 · Jalankan aplikasi lab; siapkan dua akun uji (pelanggan A dan B).

```bash
source .venv/bin/activate
python api/db.py && python api/app.py          # http://localhost:5000
```

Di terminal lain, ambil token kedua akun:

```bash
TA=$(curl -s -X POST localhost:5000/login -H 'Content-Type: application/json' \
      -d '{"username":"alice","password":"alice123"}' | python -c 'import json,sys;print(json.load(sys.stdin)["auth"]["token"])')
TB=$(curl -s -X POST localhost:5000/login -H 'Content-Type: application/json' \
      -d '{"username":"budi","password":"budi123"}' | python -c 'import json,sys;print(json.load(sys.stdin)["auth"]["token"])')
```

### Langkah 2 · Pindai dengan HawkScan (dua profil) atau ZAP (token login) memakai openapi.yaml.

**Jalur StackHawk.** `stackhawk.yml` menunjuk `openapi.yaml`, login JSON `/login`, token di `auth.token`,
header `Authorization: Bearer`, `testPath: /orders`, dan **dua profil** (`pelanggan-a`, `pelanggan-b`).
Dua profil adalah syarat *business logic testing* HawkScan untuk BOLA/BFLA.

```bash
export HAWK_API_KEY=... HAWK_APP_ID=...
docker run --rm -v "$PWD":/hawk:rw -t --network host \
  -e API_KEY="$HAWK_API_KEY" -e HAWK_APP_ID="$HAWK_APP_ID" stackhawk/hawkscan
```

**Jalur ZAP.** Satu token login dikirim lewat variabel autentikasi ZAP:

```bash
mkdir -p /tmp/spec && cp openapi.yaml /tmp/spec/
python -m http.server 8081 --bind 127.0.0.1 --directory /tmp/spec &   # hanya openapi.yaml
docker run --rm --network host -e ZAP_AUTH_HEADER=Authorization \
  -e ZAP_AUTH_HEADER_VALUE="Bearer $TB" -e ZAP_AUTH_HEADER_SITE=localhost \
  -v "$PWD":/zap/wrk:rw -t ghcr.io/zaproxy/zaproxy:stable \
  zap-api-scan.py -t http://localhost:8081/openapi.yaml -f openapi -r zap.html
```

ZAP menguji endpoint di balik login (injeksi, header, dsb.), tetapi tidak membandingkan dua pengguna.
Untuk BOLA, buktikan manual dengan cURL dua akun:

```bash
curl -s localhost:5000/orders/101 -H "Authorization: Bearer $TB"   # milik alice, dibaca budi → 200 (RENTAN)
```

Di CI, `.github/workflows/dast.yml` menjalankan kedua jalur pada setiap PR (job `hawkscan` hanya
bila secret `HAWK_API_KEY` ada).

### Langkah 3 · Berikan temuan + cURL ke Claude; minta telusuri baris penyebab dan patch.

```text
> Temuan DAST: BOLA (OWASP API1:2023). Bukti:
  curl -s localhost:5000/orders/101 -H "Authorization: Bearer <token budi>" → 200, berisi pesanan
  user_id 1 (alice). Telusuri baris penyebab di api/app.py dan usulkan patch minimal.
  Respons untuk pesanan milik orang lain harus 404 (jangan bocorkan keberadaannya).
  Tulis test regresi dulu.
```

Baris penyebab yang diharapkan: `order_detail` mengambil pesanan hanya dengan `WHERE id = ?`
tanpa memeriksa `user_id`. Patch: bandingkan `row["user_id"]` dengan `g.user["id"]`, lalu `abort(404)`.

### Langkah 4 · Tambahkan test: B tidak boleh membaca pesanan A; pindai ulang sampai bersih.

Test regresi `tests/test_bola.py`:

```python
def test_budi_tidak_bisa_lihat_pesanan_alice(client):
    token_budi = login(client, "budi", "budi123")
    assert client.get("/orders/101", headers=auth(token_budi)).status_code == 404
```

Tambahkan juga kasus positif (alice membaca 101, budi membaca 102 → 200). Jalankan
`python -m pytest -q`, ulangi cURL (harus 404), pindai ulang sampai temuan BOLA hilang, lalu PR.

## Bukti selesai

- cURL sebelum patch (200) dan sesudah patch (404).
- Laporan HawkScan (tanpa temuan BOLA High setelah patch) atau laporan ZAP `zap.html` sebagai artefak.
- `tests/test_bola.py` lulus; test lama tetap lulus.
- Workflow **DAST** berjalan di PR.

`order_detail` (`api/app.py`), dan `tests/test_bola.py`.

Catatan jujur tentang alat: BOLA adalah bug logika otorisasi. DAST generik dengan satu sesi login
umumnya tidak bisa menemukannya; butuh perbandingan antar-pengguna (profil HawkScan) atau uji manual
dua akun. Itulah sebabnya slide menekankan dua akun uji, dan perbaikannya dikunci dengan test regresi.

Jebakan slide: memindai tanpa login. Semua endpoint di balik `@login_required` hanya menjawab 401,
sehingga tidak pernah benar-benar diuji.
