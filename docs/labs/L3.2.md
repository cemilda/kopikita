## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Mengeraskan semua workflow repo lab dan menambah agen digest terjadwal yang berizin minimal.

1. Audit tiap workflow: catat izin, action, dan secret yang dipakai.
2. Tambahkan permissions minimal; pin action pihak ketiga ke commit SHA.
3. Tambahkan security-digest.yml; jalankan dengan workflow_dispatch.
4. Minta Claude me-review diff workflow; Anda yang memutuskan.

**Jebakan umum.** Pin SHA dari fork tak resmi; pastikan SHA berasal dari repo asli action.

## Langkah rinci

### Langkah 1 · Audit tiap workflow: catat izin, action, dan secret yang dipakai.

Untuk setiap berkas di `.github/workflows/`, catat di `docs/hasil/L3.2-audit-workflow.md`:

| Workflow | `permissions` | Action (tag atau SHA?) | Secret yang dipakai | Masalah |
| --- | --- | --- | --- | --- |

Bantuan cepat:

```bash
grep -n "permissions\|uses:\|secrets\." .github/workflows/*.yml
```

Pertanyaan pemandu: workflow mana yang `write-all`? Workflow mana tanpa blok `permissions`
(mewarisi default repo)? Secret mana yang diekspos ke job yang tidak memakainya?

### Langkah 2 · Tambahkan permissions minimal; pin action pihak ketiga ke commit SHA.

Perbaiki:

- `ci.yml`: `permissions: contents: read`; hapus `env: PAYMENT_API_KEY` (test tidak memakainya).
- `deploy.yml`: tambahkan `permissions: contents: read`. Access key AWS statis **dicatat** sebagai
  risiko terbuka; penggantinya (OIDC) dikerjakan di Lab L4.3.
- Pin semua action ke commit SHA penuh dengan komentar versi:

```bash
git ls-remote --tags https://github.com/actions/checkout 'v7.0.1*'
git ls-remote --tags https://github.com/github/codeql-action 'v4.39.1*'
```

Untuk tag beranotasi muncul dua baris: pakai SHA pada baris `^{}` (commit), bukan SHA objek tag.

```yaml
- uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
- uses: github/codeql-action/init@9b3254085494b55a0f7c4c2b3d2d52cc712ce370 # v4.39.1
```

Komentar `# v7.0.1` membuat Dependabot (`github-actions`) tetap bisa mengusulkan pembaruan SHA.

### Langkah 3 · Tambahkan security-digest.yml; jalankan dengan workflow_dispatch.

Tambahkan `.github/workflows/security-digest.yml` dengan pola **agen menyusun, pipeline bertindak**:

1. `schedule: cron "7 0 * * 1"` (Senin 00.07 UTC = 07.07 WIB) dan `workflow_dispatch`.
2. `permissions: contents: read, issues: write, security-events: read`.
3. Langkah `gh api` mengambil alert code scanning dan Dependabot 7 hari terakhir ke `code-scanning.json`
   dan `dependabot.json`.
4. `anthropics/claude-code-action` (dipin SHA) dengan `prompt` (agent mode) yang meminta `digest.md`,
   `github_token: ${{ github.token }}`, dan
   `claude_args: --max-turns 8 --allowedTools "Read,Write"`.
5. Langkah `gh issue create --body-file digest.md` membuat issue.

Merge ke `lab/L3.2-start`, lalu jalankan:

```bash
gh workflow run security-digest.yml --ref lab/L3.2-start
gh run watch
gh issue list --search "Security digest"
```

### Langkah 4 · Minta Claude me-review diff workflow; Anda yang memutuskan.

Minta Claude me-review diff workflow sebagai reviewer kedua:

```text
> Review git diff lab/L3.2-start...kerja/L3.2 -- .github/workflows/. Cari: izin berlebih,
  action tanpa pin SHA, secret yang terekspos, ekspresi ${{ }} dari input tidak tepercaya
  di dalam run:, dan pemicu berbahaya (pull_request_target). Jangan ubah berkas.
```

Anda yang memutuskan: verifikasi setiap SHA yang disarankan Claude dengan `git ls-remote` ke repo resmi
sebelum menerimanya.

## Bukti selesai

- Tabel audit untuk empat workflow (tiga lama + digest).
- `grep -n "uses:" .github/workflows/*.yml` tidak menyisakan tag tanpa SHA.
- Tidak ada `write-all`; setiap job punya izin minimal.
- Satu issue "Security digest <tanggal>" dari `workflow_dispatch`, dengan angka yang cocok dengan
  `code-scanning.json` dan `dependabot.json` di log job.
