## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Menutup jalur kepercayaan implisit di repo lab: berkas sensitif, karakter tersembunyi, dan identitas agen.

1. Pastikan CODEOWNERS mencakup CLAUDE.md, .claude/, .github/, infra/.
2. Tambahkan cek CI untuk karakter bidi (U+202A–202E) dan zero-width.
3. Ganti secret cloud statis dengan OIDC; beri agen token sendiri.
4. Wajibkan label dan satu reviewer manusia untuk PR buatan agen.

**Jebakan umum.** Menganggap commit buatan agen "sudah di-review" karena agen menulis ringkasan PR yang meyakinkan.

## Persiapan

- Branch start berisi CODEOWNERS dan ruleset L3.4, workflow yang sudah dipin (L3.2), dan
  `deploy.yml` yang masih memakai access key AWS statis.
- Jadikan `lab/L4.3-start` default branch (ruleset dan CODEOWNERS mengikuti default branch).
- Untuk OIDC sungguhan: akses ke akun AWS latihan. Tanpa akun AWS, kerjakan berkasnya dan trust policy
  saja; job deploy cukup diperiksa, tidak dijalankan.

```bash
git switch lab/L4.3-start && git switch -c kerja/L4.3
```

## Langkah rinci

### Langkah 1 · Pastikan CODEOWNERS mencakup CLAUDE.md, .claude/, .github/, infra/.

```bash
cat .github/CODEOWNERS
```

Pastikan empat jalur slide tercakup: `/CLAUDE.md`, `/.claude/`, `/.github/`, `/infra/`. Tambahkan
jalur yang sejak L3.4 bertambah dan juga mengarahkan perilaku otomatis: `/agent/` (kode agen triase),
`/scripts/` (skrip gerbang CI), `/policy/` (Rego). Verifikasi di GitHub: buka berkas CODEOWNERS di UI;
baris yang salah (tim tidak ada) ditandai merah.

### Langkah 2 · Tambahkan cek CI untuk karakter bidi (U+202A–202E) dan zero-width.

Buat `scripts/check_hidden_chars.py` yang memindai karakter bidi (U+202A–U+202E, U+2066–U+2069) dan
zero-width (U+200B, U+200C, U+200D, U+2060, U+FEFF), plus bonus *tag characters* (U+E0000–U+E007F)
yang dipakai menyelundupkan instruksi ke berkas aturan agen. Pindai **seluruh repo** termasuk
`CLAUDE.md`, `.claude/`, dan `.github/`; keluar kode 1 bila ada temuan.

```bash
python scripts/check_hidden_chars.py .        # "Tidak ada karakter tersembunyi."
```

Tambahkan `.github/workflows/hidden-chars.yml` (job `scan`) dan test, termasuk test bahwa repo sendiri bersih.
Uji dengan PR berisi karakter tersembunyi: `gh pr create --base lab/L4.3-solution --head pr/L4.3-pr-bidi`.
Check **Hidden chars** harus merah dan menunjuk `web/lib/diskon.js` serta `docs/promo.md`.

Di editor, karakter itu tidak terlihat. Lihat dengan `grep -nP '[\x{202A}-\x{202E}\x{2066}-\x{2069}\x{200B}]' -r web docs`
atau `cat -A web/lib/diskon.js`.

### Langkah 3 · Ganti secret cloud statis dengan OIDC; beri agen token sendiri.

**Secret cloud statis → OIDC.** Ubah `deploy.yml`:

```yaml
jobs:
  deploy:
    permissions:
      contents: read
      id-token: write          # hanya job ini
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: aws-actions/configure-aws-credentials@e1253824e5c10ff9df46874f81ed3ec929e19cfd # v6.3.0
        with:
          role-to-assume: ${{ vars.AWS_DEPLOY_ROLE_ARN }}
          aws-region: ap-southeast-3
```

Di AWS, trust policy role membatasi klaim `sub` ke `repo:<org>/kopikita-vuln:ref:refs/heads/main`
(contoh lengkap di kunci jawaban). Setelah berhasil, hapus secret `AWS_ACCESS_KEY_ID` dan
`AWS_SECRET_ACCESS_KEY`, dan cabut kuncinya di IAM.

**Agen punya token sendiri.** Agen triase (L3.1) memakai fine-grained PAT atau GitHub App khusus agen
yang hanya untuk repo ini, berizin Contents + Pull requests, tanpa Administration, masa berlaku pendek.
Agen di CI memakai `GITHUB_TOKEN` job dengan izin minimal. Catat di `docs/hasil/L4.3-identitas-agen.md`.

### Langkah 4 · Wajibkan label dan satu reviewer manusia untuk PR buatan agen.

Tambahkan `.github/workflows/agent-pr-gate.yml` (job `label-agen`): PR dari branch `fix/*` atau
`claude/*`, atau dari akun Bot, gagal bila tidak berlabel `ai-generated`. Nilai dari event
(`github.head_ref`, label) dikirim lewat `env:`, bukan disisipkan ke `run:`, karena nama branch bisa
diatur penyerang (script injection).

Perbarui ruleset dan terapkan:

```bash
bash scripts/terapkan-ruleset.sh <owner>/kopikita-vuln
```

`main-dilindungi` sekarang mewajibkan 1 approval, review code owner, approval ulang setelah push
terakhir, dan status check `label-agen` + `scan`. Tambahkan juga checklist "Dibantu/ditulis agen AI"
di `.github/pull_request_template.md`.

Uji: jalankan agen L3.1 (atau buat branch `fix/uji` sendiri) tanpa label → check `label-agen` merah;
tambahkan label `ai-generated` → hijau, tetapi merge tetap menunggu satu reviewer manusia.

## Bukti selesai

- CODEOWNERS mencakup `CLAUDE.md`, `.claude/`, `.github/`, `infra/` (+ `agent/`, `scripts/`, `policy/`).
- PR `pr/L4.3-pr-bidi` gagal di **Hidden chars**; `pytest -q` lulus di branch Anda.
- `deploy.yml` tanpa access key statis; `id-token: write` hanya di job deploy.
- PR `fix/*` tanpa label gagal di **Gerbang PR agen**; dengan label tetap butuh approval manusia.
