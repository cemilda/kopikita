## Langkah rinci

### Langkah 1 · Pasang pre-commit hook; coba commit kunci privat palsu.

Pasang hook (detect-private-key, detect-secrets dengan baseline, gitleaks; pip-audit di stage manual):

```bash
bash scripts/pre-commit-security.sh
```

Skrip membuat `.pre-commit-config.yaml` dan `.secrets.baseline`. Baseline mencatat rahasia yang
**sudah ada** (key palsu di `api/config.py`) agar hook hanya menolak rahasia **baru**.

Uji dengan kunci privat palsu:

```bash
printf -- '-----BEGIN OPENSSH PRIVATE KEY-----\nAAAAb3BlbnNzaC1rZXktdjEAAAAAuji-palsu\n-----END OPENSSH PRIVATE KEY-----\n' > kunci-uji.txt
git add kunci-uji.txt
git commit -m "uji hook"        # DITOLAK: detect-private-key dan gitleaks gagal
```

### Langkah 2 · Lewati hook dengan --no-verify; git push token uji, baca penolakan.

Lewati hook untuk melihat lapis kedua (push protection di GitHub):

1. Buat token uji yang segera dicabut: GitHub → Settings → Developer settings →
   **Fine-grained tokens → Generate new token**. Nama `uji-push-protection`, kedaluwarsa 1 hari,
   *Repository access: Public repositories (read-only)*, tanpa izin tambahan.
2. Tulis ke berkas dan lewati hook:

   ```bash
   echo "GH_TOKEN_UJI=<tempel token>" > token-uji.txt
   git add token-uji.txt
   git commit --no-verify -m "uji push protection"
   git push -u origin kerja/L1.3
   ```

3. Baca penolakan `GH013: Repository rule violations found` / *Push cannot contain secrets*:
   jenis rahasia, berkas, baris, dan tautan untuk *bypass* (jangan dipakai).
4. **Segera hapus token** di halaman Fine-grained tokens, lalu bersihkan commit lokal:

   ```bash
   git reset --hard HEAD~1 && rm -f kunci-uji.txt token-uji.txt
   ```

### Langkah 3 · Tambahkan custom pattern untuk format API key internal kopikita_.

Format API key internal KopiKita (`kopikita_live_` + 32 hex) tidak dikenali pola bawaan GitHub.
Buat custom pattern: Settings → Advanced Security → Secret scanning → **Custom patterns → New pattern**

| Kolom | Nilai |
| --- | --- |
| Pattern name | KopiKita API key |
| Secret format | `kopikita_(live\|test)_[a-f0-9]{32}` |
| Test string | `PAYMENT_API_KEY = "kopikita_live_0123456789abcdef0123456789abcdef"` |

**Save and dry run** → pastikan cocok → **Publish pattern** → aktifkan **push protection** untuk
pattern itu. Uji: tambahkan key berformat sama ke berkas apa pun, commit `--no-verify`, push → ditolak.

Lalu pindahkan key dari kode ke environment (langkah "hapus" di runbook): di `api/config.py`
ganti nilai tertanam dengan `os.environ.get("PAYMENT_API_KEY", "")`, tambahkan
`PAYMENT_API_KEY=` ke `.env.example`, dan tambahkan test `tests/test_tanpa_rahasia_di_kode.py`
yang gagal bila pola `kopikita_(live|test)_` muncul lagi di `api/`.

### Langkah 4 · Buka alert di histori repo; tulis runbook: cabut, hapus, audit.

Setelah pattern dipublikasikan, GitHub memindai ulang seluruh histori. Buka
**Security → Secret scanning**, filter *custom patterns*. Harus ada dua alert:

- `kopikita_live_7c2e…` di `api/config.py` (key yang tertanam di kode), dan
- `kopikita_live_0011…` yang **hanya ada di histori** (commit "Tambah integrasi gateway pembayaran").

Tulis `docs/runbook/kebocoran-rahasia.md` dengan urutan **cabut → hapus → audit**:
cabut key di penyedia dulu (karena rahasia yang pernah ter-push dianggap sudah dicuri),
baru hapus dari kode/histori, lalu audit pemakaian. Tutup alert dengan status **Revoked**.

```bash
git add api/config.py .env.example tests/test_tanpa_rahasia_di_kode.py docs/
git commit -m "L1.3: key dari environment, custom pattern, runbook"
git push -u origin kerja/L1.3 && gh pr create --base lab/L1.3-start --fill
```

## Bukti selesai

- Tangkapan layar commit ditolak hook (langkah 1) dan push ditolak push protection (langkah 2).
- Token uji sudah dihapus di GitHub.
- Custom pattern "KopiKita API key" terbit dengan push protection aktif.
- Dua alert custom pattern, termasuk satu yang hanya ada di histori.
- `pytest -q` lulus, termasuk `tests/test_tanpa_rahasia_di_kode.py` (11 test).
- `docs/runbook/kebocoran-rahasia.md` dengan urutan cabut, hapus, audit.
