## Langkah rinci

### Langkah 1 · Buka Security Overview; ekspor alert terbuka lewat gh api ke JSON.

Buka **Organisasi → Security → Overview**: lihat tren alert terbuka, *Mean time to remediate*, dan
alert per repo. Lalu ekspor data mentah repo Anda:

```bash
gh api --paginate "repos/{owner}/{repo}/code-scanning/alerts?per_page=100&state=all" \
  --jq '.[]' | jq -s . > alerts.json
jq length alerts.json
```

Data mentah ini sumber kebenaran laporan. Jangan meminta AI "menghitung dari dashboard".

### Langkah 2 · Minta Claude menulis skrip penghitung backlog per severity dan MTTR.

```text
> Tulis scripts/risk_report.py: baca alerts.json (format API code scanning GitHub) dan cetak JSON
  berisi total, backlog alert open per severity (pakai rule.security_severity_level, fallback
  rule.severity), MTTR dalam hari untuk alert yang punya fixed_at, jumlah alert dismissed tanpa
  dismissed_reason, dan tiga risiko teratas (open; severity tertinggi lalu paling lama).
  Tulis test di tests/test_risk_report.py dengan fixture kecil yang angkanya bisa dihitung tangan.
```

Periksa test-nya: apakah angka di fixture bisa Anda hitung sendiri? (Contoh: MTTR (4 + 2) / 2 = 3,0 hari.)

```bash
python -m pytest -q tests/test_risk_report.py
python scripts/risk_report.py --alerts alerts.json > docs/hasil/metrik.json
```

### Langkah 3 · Minta ringkasan satu halaman untuk manajer: tiga risiko teratas.

```text
> Dari docs/hasil/metrik.json SAJA, tulis docs/hasil/L4.2-laporan.md: satu halaman untuk manajer
  non-teknis. Ringkasan 3 kalimat, tabel tiga risiko teratas (alert, severity, lokasi, dampak bisnis,
  tindakan dan pemilik). Jangan menambah angka yang tidak ada di JSON.
```

Claude menulis narasi; angka berasal dari skrip.

### Langkah 4 · Verifikasi dua angka secara manual terhadap dashboard.

Cocokkan dua angka laporan dengan dashboard, dan isi tabel verifikasi di akhir laporan:

| Angka | Cek manual |
| --- | --- |
| Alert open critical | Security → Code scanning, filter `is:open severity:critical` |
| Alert open high | Security Overview, kolom *High* untuk repo ini |

Bila tidak cocok, cari penyebabnya (mis. filter branch berbeda, alert dari tool lain, paginasi
yang terlewat) sebelum laporan dikirim.
