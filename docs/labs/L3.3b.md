## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Membuat image repo lab bisa dibuktikan isi, asal, dan keutuhannya sebelum deploy.

1. Tambahkan langkah Trivy SBOM (CycloneDX) dan unggah sebagai artefak.
2. Tandatangani image keyless dengan cosign; izin id-token hanya di job itu.
3. Tambahkan attest-build-provenance; periksa attestation di repo.
4. Verifikasi dengan identitas workflow persis; coba identitas salah dan lihat gagal.

**Jebakan umum.** Memberi id-token: write ke seluruh workflow, atau memverifikasi dengan regex yang menerima siapa pun.

## Langkah rinci

### Langkah 1 · Tambahkan langkah Trivy SBOM (CycloneDX) dan unggah sebagai artefak.

Buat `.github/workflows/release.yml` (pemicu: tag `v*` dan `workflow_dispatch`). Setelah
`docker/build-push-action` mendorong image dan memberi `digest`, tambahkan SBOM:

```yaml
- name: SBOM (CycloneDX)
  uses: aquasecurity/trivy-action@ed142fd0673e97e23eac54620cfb913e5ce36c25 # v0.36.0
  with:
    scan-type: image
    image-ref: ${{ env.IMAGE }}@${{ steps.build.outputs.digest }}
    format: cyclonedx
    output: sbom.json
- uses: actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7.0.2
  with: {name: sbom, path: sbom.json}
```

`IMAGE` dihitung sekali: `echo "IMAGE=ghcr.io/${GITHUB_REPOSITORY,,}" >> "$GITHUB_ENV"`
(GHCR menolak huruf besar). Selalu rujuk image dengan **digest**, bukan tag.

### Langkah 2 · Tandatangani image keyless dengan cosign; izin id-token hanya di job itu.

```yaml
permissions:
  contents: read            # tingkat workflow: minimal
jobs:
  build-sign:
    permissions:
      contents: read
      packages: write
      id-token: write       # HANYA job ini: identitas OIDC untuk cosign keyless
      attestations: write
    steps:
      # ...
      - uses: sigstore/cosign-installer@6f9f17788090df1f26f669e9d70d6ae9567deba6 # v4.1.2
      - run: cosign sign --yes ${{ env.IMAGE }}@${{ steps.build.outputs.digest }}
```

Keyless: cosign meminta sertifikat berumur pendek dari Fulcio untuk identitas OIDC workflow ini,
menandatangani digest, dan mencatat tanda tangan di log transparansi Rekor. Tidak ada kunci privat
yang perlu disimpan.

### Langkah 3 · Tambahkan attest-build-provenance; periksa attestation di repo.

```yaml
- uses: actions/attest-build-provenance@4d101475d8b20a2381f78447822ac1eab6504dd8 # v4.2.2
  with:
    subject-name: ${{ env.IMAGE }}
    subject-digest: ${{ steps.build.outputs.digest }}
    push-to-registry: true
```

Merge, jalankan `gh workflow run release.yml --ref lab/L3.3b-start`, lalu periksa tab
**Actions → Attestations** di repo (provenance SLSA untuk digest image) dan artefak `sbom` di run.

### Langkah 4 · Verifikasi dengan identitas workflow persis; coba identitas salah dan lihat gagal.

```bash
export GITHUB_REPOSITORY=<owner>/kopikita-vuln
export IMAGE_REF=refs/heads/lab/L3.3b-start          # ref tempat workflow dijalankan
DIGEST=$(gh api "users/<owner>/packages/container/kopikita-vuln/versions" --jq '.[0].name')   # untuk org: orgs/<org>/packages/...
bash scripts/verify-image.sh "ghcr.io/<owner>/kopikita-vuln@${DIGEST}"
```

Skrip memakai identitas **persis**:
`--certificate-identity https://github.com/<owner>/kopikita-vuln/.github/workflows/release.yml@<ref>`
dan `--certificate-oidc-issuer https://token.actions.githubusercontent.com`, lalu `gh attestation verify`.

Coba identitas salah (harus **gagal**):

```bash
IMAGE_REF=refs/heads/main bash scripts/verify-image.sh "ghcr.io/<owner>/kopikita-vuln@${DIGEST}"
cosign verify --certificate-identity "https://github.com/orang-lain/repo/.github/workflows/release.yml@refs/heads/main" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com "ghcr.io/<owner>/kopikita-vuln@${DIGEST}"
```

## Bukti selesai

- Run `Release image` hijau; artefak `sbom` berisi `sbom.json` CycloneDX.
- Attestation provenance tampil di repo untuk digest image.
- `verify-image.sh` sukses dengan identitas benar dan gagal dengan identitas/ref salah.
- `id-token: write` hanya ada di job `build-sign`.

Tiga pertanyaan yang dijawab rilis ini: **isi** (SBOM), **asal** (provenance: repo, workflow, commit
yang membangun), dan **keutuhan** (tanda tangan atas digest).

Jebakan slide: `id-token: write` di tingkat workflow (semua job bisa meminta identitas penanda
tangan), atau verifikasi dengan `--certificate-identity-regexp '.*'` yang menerima tanda tangan
dari workflow siapa pun di GitHub.
