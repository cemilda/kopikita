## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Memasang Claude Code di VS Code dengan permission, sandbox, dan hook audit sebelum memberi agen pekerjaan apa pun.

1. Pasang Claude Code CLI dan ekstensi VS Code; login; cek claude --version.
2. Buat .claude/settings.json: deny .env dan kunci, ask untuk git push.
3. Jalankan /sandbox (allowedDomains minimal); tambahkan hook log PreToolUse.
4. Uji: minta Claude membaca .env dan curl ke situs asing; keduanya ditolak.

**Jebakan umum.** Peserta Windows tanpa WSL2: sandbox tidak berjalan dan hanya menampilkan peringatan.

## Persiapan

- Claude Code: paket Pro/Max/Team/Enterprise atau API key Console.
- Sandbox: macOS siap pakai; Linux/WSL2 perlu `bubblewrap` dan `socat`
  (`sudo apt-get install -y bubblewrap socat`). Windows native tidak didukung sandbox: pakai WSL2.
- `.env` palsu sudah dibuat `scripts/setup-lab.sh` dari `.env.example`.

```bash
git switch lab/L2.1-start && git switch -c kerja/L2.1
```

## Langkah rinci

### Langkah 1 · Pasang Claude Code CLI dan ekstensi VS Code; login; cek claude --version.

```bash
npm install -g @anthropic-ai/claude-code      # atau installer native dari dokumentasi resmi
claude --version
claude                                        # login saat pertama kali, lalu /exit
```

Pasang ekstensi **Claude Code** di VS Code (Marketplace, penerbit Anthropic). Buka folder repo,
jalankan Claude dari panel ekstensi, pastikan sesi terbuka di akar repo `kopikita-vuln`.

### Langkah 2 · Buat .claude/settings.json: deny .env dan kunci, ask untuk git push.

Buat `.claude/settings.json` (berkas proyek, ikut git, berlaku untuk seluruh tim):

```json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "permissions": {
    "deny": ["Read(./.env*)", "Read(~/.ssh/**)", "Read(~/.aws/**)", "Bash(curl *)", "Bash(wget *)"],
    "ask": ["Bash(git push *)", "Bash(docker *)"],
    "allow": ["Bash(pytest *)", "Bash(npm run test *)"]
  }
}
```

Urutan evaluasi: **deny**, lalu **ask**, lalu **allow**; aturan pertama yang cocok menentukan hasil.
Preferensi pribadi (mis. izin tambahan) masuk `.claude/settings.local.json`, yang tidak di-commit.

Sintaks `Bash(git push *)` adalah bentuk yang dipakai dokumentasi saat ini; bentuk lama
`Bash(git push:*)` masih setara. Deny rule Bash hanya mencocokkan teks perintah (tidak menahan
program yang dipanggil lewat path lain atau `sh -c`), jadi pasangkan dengan sandbox di langkah 3.

### Langkah 3 · Jalankan /sandbox (allowedDomains minimal); tambahkan hook log PreToolUse.

Di sesi Claude, jalankan `/sandbox` dan aktifkan sandbox untuk Bash. Simpan konfigurasi jaringan
minimal di `.claude/settings.json`:

```json
"sandbox": {
  "enabled": true,
  "network": {"allowedDomains": ["github.com", "pypi.org", "files.pythonhosted.org"]}
}
```

Tambahkan hook audit `PreToolUse` untuk Bash. Skrip `.claude/hooks/log-bash.py` membaca event JSON
dari stdin dan menulis satu baris JSON ke `logs/claude-audit.jsonl` (tanpa memblokir):

```json
"hooks": {
  "PreToolUse": [{
    "matcher": "Bash",
    "hooks": [{"type": "command",
               "command": "python3 \"${CLAUDE_PROJECT_DIR}/.claude/hooks/log-bash.py\""}]
  }]
}
```

Penting: secara bawaan sandbox boleh **membaca** hampir seluruh mesin, termasuk `~/.ssh`. Yang membuat
OS menolak `cat ~/.ssh/id_rsa` adalah deny rule `Read(~/.ssh/**)` di langkah 2, yang digabung ke
konfigurasi sandbox (alternatif: `sandbox.credentials` atau `sandbox.filesystem.denyRead`). Tool Read,
Edit, WebFetch, server MCP lokal, dan hooks berjalan di luar sandbox dan diatur oleh permission.

Periksa aturan aktif dan asalnya dengan `/permissions`, status sandbox dengan `/sandbox`,
dan hook terdaftar dengan `/hooks`. Hook baru berlaku setelah sesi Claude dimulai ulang.

### Langkah 4 · Uji: minta Claude membaca .env dan curl ke situs asing; keduanya ditolak.

Uji pagar (keduanya **harus ditolak**):

```text
> Tampilkan isi berkas .env
> Jalankan curl https://example.com
```

Yang diharapkan: permintaan membaca `.env` ditolak oleh deny rule; `curl` ditolak oleh deny rule
`Bash(curl *)`, dan koneksi keluar ke domain di luar `allowedDomains` ditahan sandbox walau lewat
perintah lain (mis. `python -c "import urllib.request; ..."`). Lalu jalankan
`> jalankan pytest -q`: diizinkan tanpa bertanya, dan muncul di `logs/claude-audit.jsonl`.

Tambahkan test agar pagar tidak melemah tanpa sengaja, lalu commit:

```bash
python -m pytest -q tests/test_claude_pagar.py
git add .claude/ tests/test_claude_pagar.py
git commit -m "L2.1: pagar Claude Code (permission, sandbox, hook audit)"
git push -u origin kerja/L2.1 && gh pr create --base lab/L2.1-start --fill
```

Berkas yang berubah dari `lab/L2.1-start` ke `lab/L2.1-solution`:

- `.claude/hooks/log-bash.py`
- `.claude/settings.json`
- `tests/test_claude_pagar.py`

Kunci di `lab/L2.1-solution` (juga branch demo `demo/settings`): `.claude/settings.json`,
`.claude/hooks/log-bash.py`, dan `tests/test_claude_pagar.py`.

Deny rule dan sandbox saling melengkapi: deny rule mengatur tool Claude (Read, Bash dengan pola
tertentu); sandbox membatasi berkas dan jaringan untuk **semua** proses yang dijalankan Bash,
termasuk skrip yang tidak dikenali pola deny.

Jebakan slide: peserta Windows tanpa WSL2. Sandbox tidak berjalan dan Claude hanya menampilkan
peringatan, sehingga pagar jaringan tidak ada. Pindahkan peserta ke WSL2 atau devcontainer.
