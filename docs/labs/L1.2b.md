## Langkah rinci

### Langkah 1 · Minta Claude menulis rule taint: source request.args, sink cursor.execute.

Buka Claude Code di akar repo dan beri prompt yang spesifik (Claude menulis draf, test yang membuktikan):

```text
Tulis rule Semgrep mode taint di rules/kopikita-sql-taint.yaml untuk Python.
Source: request.args.get(...), request.form[...], dan request.get_json(...).
Sink: argumen PERTAMA dari $CUR.execute($Q, ...) (pakai focus-metavariable: $Q),
supaya query berparameter seperti execute("... ?", (x,)) tidak ditandai.
Severity ERROR, metadata cwe CWE-89. Jangan jalankan scan dulu.
```

Periksa hasilnya: `mode: taint`, tiga `pattern-sources`, `pattern-sinks` dengan `focus-metavariable`.
Mengapa `request.get_json`? Endpoint login KopiKita membaca body JSON, bukan `request.args`.

### Langkah 2 · Tambahkan sanitizer internal kopikita.safe_sql ke rule.

Tambahkan sanitizer internal tim. `kopikita.safe_sql()` di `api/kopikita/__init__.py` adalah
allowlist nama kolom: nilai di luar `{"name", "price", "category"}` ditolak dengan `ValueError`.

```yaml
pattern-sanitizers:
  - pattern: kopikita.safe_sql(...)
```

Tanpa sanitizer ini, `ORDER BY {sort}` di endpoint `products` akan ikut ditandai: itu false
positive yang sama dengan alert 6 CodeQL di catatan triase L1.2.

### Langkah 3 · Tulis contoh ruleid: dan ok:; jalankan semgrep --test sampai lulus.

Buat berkas test bernama sama dengan rule: `rules/kopikita-sql-taint.py`. Setiap kasus diberi
anotasi di baris sebelum sink:

```python
name = request.args.get("name")
# ruleid: kopikita-sql-taint
cur.execute("SELECT * FROM users WHERE username = '" + name + "'")

sort = kopikita.safe_sql(request.args.get("sort", "name"))
# ok: kopikita-sql-taint
cur.execute(f"SELECT * FROM products ORDER BY {sort}")
```

Minimal: tiga `ruleid:` (args, form, get_json) dan dua `ok:` (berparameter, tersanitasi). Lalu:

```bash
semgrep --test rules/
```

Ulangi perbaikan rule sampai keluarannya `All tests passed`. Rule yang belum lulus test **tidak**
boleh masuk CI.

### Langkah 4 · Jalankan rule ke seluruh repo; bandingkan dengan alert CodeQL.

Jalankan rule ke kode aplikasi dan bandingkan:

```bash
semgrep scan --config rules/ api/
```

Hasil yang diharapkan: temuan di `api/app.py` fungsi `login` (`cur.execute(query)`), yaitu
alert 1 CodeQL, dan **tidak ada** temuan di `products` (sanitizer bekerja).

Masukkan ke CI: `.github/workflows/semgrep.yml` menjalankan `semgrep --test rules/` lebih dulu,
lalu memindai `api/` dan mengunggah SARIF dengan kategori `semgrep-kopikita`.
Supaya CodeQL tidak memindai berkas test rule yang sengaja rentan, tambahkan
`.github/codeql/codeql-config.yml` berisi `paths-ignore: [rules/]` dan rujuk dari `codeql.yml`
lewat `config-file`.

```bash
git add rules/ .github/
git commit -m "L1.2b: rule taint Semgrep untuk SQL KopiKita"
git push -u origin kerja/L1.2b && gh pr create --base lab/L1.2b-start --fill
```

## Bukti selesai

- `semgrep --test rules/` → semua test lulus.
- `semgrep scan --config rules/ api/` → temuan di `login`, tidak ada temuan di `products`.
- Workflow **Semgrep (rule kustom)** hijau di PR; di tab Security muncul alert kategori
  `semgrep-kopikita` berdampingan dengan CodeQL.
- Tabel singkat di deskripsi PR: alert mana yang ditemukan keduanya, mana yang hanya oleh salah satu.

atau tanpa sanitizer) menandai semua query, termasuk yang berparameter. Presisi turun dan
developer berhenti percaya pada scanner.
