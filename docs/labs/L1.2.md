## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Mengaktifkan code scanning, secret scanning, dan Dependabot pada repo lab, lalu menriase alert CodeQL pertama.

1. Aktifkan CodeQL advanced setup (security-extended), secret scanning, Dependabot.
2. Tambahkan SECURITY.md: versi didukung, cara lapor, target waktu respons.
3. Buka tiga alert CodeQL: catat CWE, source, sink, berkas; klasifikasikan.
4. Simpan catatan triase; dipakai lagi saat remediasi di Hari 2.

**Jebakan umum.** Menutup alert dengan "won't fix" tanpa alasan tertulis.

  Dependabot alerts gratis untuk semua repo.

## Langkah rinci

### Langkah 1 · Aktifkan CodeQL advanced setup (security-extended), secret scanning, Dependabot.

**Secret scanning dan Dependabot** (klik di UI):
Settings → **Advanced Security** → aktifkan *Dependency graph*, *Dependabot alerts*,
*Secret Protection* (secret scanning) dan *Push protection*.

**CodeQL advanced setup** (berkas workflow, bukan default setup, agar konfigurasi tercatat di git):

1. Settings → Advanced Security → Code scanning → CodeQL analysis → **Set up → Advanced**.
   GitHub membuka editor `codeql.yml`. Atau tulis sendiri di laptop:
2. Buat `.github/workflows/codeql.yml` dengan bahasa `python` dan `javascript-typescript`,
   lalu tambahkan `queries: security-extended` pada langkah `init`:

   ```yaml
   - uses: github/codeql-action/init@v4
     with:
       languages: ${{ matrix.language }}
       queries: security-extended
   ```

3. Pemicu: `push` ke `main` dan `lab/**`, `pull_request`, `workflow_dispatch`, dan `schedule` mingguan.
   Izin: `contents: read` di tingkat workflow, `security-events: write` hanya di job `analyze`.

> Catatan: action di lab ini masih memakai tag (`@v4`). Pin ke commit SHA dikerjakan di Lab L3.2.

### Langkah 2 · Tambahkan SECURITY.md: versi didukung, cara lapor, target waktu respons.

Buat `SECURITY.md` di akar repo dengan tiga bagian (mengikuti contoh Modul 02 repo
Secure-Code-AI-Dev): **Supported Versions** (tabel versi yang masih menerima perbaikan),
**Reporting a Vulnerability** (lewat *Private vulnerability reporting* GitHub, bukan issue publik),
dan **Response Timeline** (mis. konfirmasi 2 hari kerja, triase 5 hari kerja,
perbaikan Critical/High 14 hari).

Aktifkan juga Settings → Advanced Security → **Private vulnerability reporting**.

```bash
git add .github/workflows/codeql.yml SECURITY.md
git commit -m "L1.2: CodeQL advanced setup dan SECURITY.md"
git push -u origin kerja/L1.2
gh pr create --base lab/L1.2-start --fill
```

Merge PR setelah workflow **CodeQL** hijau. Push ke `lab/L1.2-start` memicu analisis penuh.

### Langkah 3 · Buka tiga alert CodeQL: catat CWE, source, sink, berkas; klasifikasikan.

Buka **Security → Code scanning**. Untuk tiga alert, catat di `docs/hasil/L1.2-triase.md`
(salin dari `docs/templates/triase.md`):

| Kolom | Dari mana |
| --- | --- |
| Rule dan CWE | judul alert dan tag CWE |
| Source | langkah pertama di **Show paths** (data masuk dari request) |
| Sink | langkah terakhir (titik berbahaya: `execute`, `open`, `log.info`) |
| Berkas dan baris | lokasi alert |
| Klasifikasi | Rentan / False positive / Tidak dipakai (used in tests) |

Alert yang diharapkan muncul di `api/app.py`: SQL injection pada `login`, path injection pada
`invoice`, Flask debug di `__main__`, dan clear-text logging password. Bisa juga muncul alert
SQL pada `products` (`ORDER BY {sort}`): itu false positive karena nilainya melewati allowlist
`kopikita.safe_sql`.

Bila alert false positive, tutup dengan **Dismiss → False positive** dan tulis alasannya di kolom komentar.

### Langkah 4 · Simpan catatan triase; dipakai lagi saat remediasi di Hari 2.

Commit catatan triase ke branch kerja (PR kedua atau lanjutkan PR yang sama):

```bash
git add docs/hasil/L1.2-triase.md
git commit -m "L1.2: catatan triase alert CodeQL"
git push
```

Catatan ini dipakai lagi di Lab L2.3 (remediasi alert 1–3), L3.1 (alert 4 oleh agen triase),
dan capstone (alert 5).
