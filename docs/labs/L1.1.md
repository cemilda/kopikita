## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Memetakan aset, pihak, dan batas kepercayaan repo kopikita-vuln, termasuk titik di mana agen AI akan bekerja.

1. Fork repo kopikita-vuln ke organisasi kelas dan clone ke laptop.
2. Daftar aset: kode, rahasia, dependensi, image, IaC, workflow.
3. Gambar batas kepercayaan: developer, agen, konten luar, MCP, CI.
4. Tandai tiga titik paling berisiko, lalu presentasikan 2 menit.

**Jebakan umum.** Lupa memasukkan konten repo (issue, PR, README) sebagai input tidak tepercaya.

## Persiapan

- Akun GitHub dan anggota organisasi kelas.
- Templat: `docs/templates/peta-aset.md` (diagram Mermaid; GitHub merender Mermaid langsung di berkas `.md`).
- Lab ini tidak memakai fitur GitHub selain fork. Tidak perlu mengganti default branch.

## Langkah rinci

### Langkah 1 · Fork repo kopikita-vuln ke organisasi kelas dan clone ke laptop.

1. Buka repo `kopikita-vuln` milik instruktur → **Fork**. Pilih organisasi kelas sebagai *owner*
   dan **hapus centang "Copy the `main` branch only"**. Semua branch `lab/*` dan `pr/*` ikut tersalin.
2. Clone dan siapkan lingkungan:

   ```bash
   gh repo clone <ORG-KELAS>/kopikita-vuln
   cd kopikita-vuln
   git branch -r | head            # pastikan origin/lab/L1.1-start ada
   git switch lab/L1.1-start
   git switch -c kerja/L1.1
   bash scripts/setup-lab.sh        # .venv, .env palsu, database, 9 test lulus
   ```

3. Salin templat: `cp docs/templates/peta-aset.md docs/hasil/L1.1-peta-aset.md` (buat folder `docs/hasil/` bila belum ada).

### Langkah 2 · Daftar aset: kode, rahasia, dependensi, image, IaC, workflow.

Isi tabel "Daftar aset" dengan menelusuri repo, bukan menebak. Petunjuk lokasi:

| Jenis aset | Lihat di |
| --- | --- |
| Kode | `api/` (Flask), `web/` (Node.js) |
| Rahasia | `api/config.py`, `.env` (lokal), secret GitHub Actions, histori git |
| Dependensi | `api/requirements.txt`, `web/package.json`, `requirements-dev.txt` |
| Image | `Dockerfile`, `docker-compose.yml` |
| IaC | `infra/main.tf`, `infra/k8s/deployment.yaml` |
| Workflow | `.github/workflows/ci.yml`, `.github/workflows/deploy.yml` |

Kolom "Siapa yang bisa mengubah" memaksa Anda berpikir tentang izin: developer, reviewer,
workflow (`GITHUB_TOKEN`), dan nanti agen AI.

### Langkah 3 · Gambar batas kepercayaan: developer, agen, konten luar, MCP, CI.

Lengkapi diagram Mermaid di templat. Minimal ada lima pihak dari slide:
**developer**, **agen** (Claude Code), **konten luar** (issue, PR, README, komentar kode dari orang
lain), **MCP** server, dan **CI** (GitHub Actions dengan secret organisasi).
Tambahkan juga penyedia model (API Anthropic) dan registry paket (PyPI, npm).

Gambar garis putus atau `subgraph` untuk setiap **batas kepercayaan**. Pertanyaan pemandu:
"Di mana agen membaca teks yang ditulis orang lain?" (jawaban: issue, PR, README, komentar kode,
output tool MCP, hasil web fetch).

### Langkah 4 · Tandai tiga titik paling berisiko, lalu presentasikan 2 menit.

Tulis tiga titik paling berisiko di bagian 3 templat, masing-masing dengan alasan satu kalimat
dan kontrol yang akan dipasang (sebut lab-nya). Presentasikan 2 menit per pasangan.

Commit hasil Anda:

```bash
git add docs/hasil/L1.1-peta-aset.md
git commit -m "L1.1: peta aset dan batas kepercayaan"
git push -u origin kerja/L1.1
```

## Kunci jawaban

Berkas yang berubah dari `lab/L1.1-start` ke `lab/L1.1-solution`:

- `docs/hasil/L1.1-peta-aset.md`

Contoh jawaban lengkap: `docs/hasil/L1.1-peta-aset.md` di `lab/L1.1-solution`.

Hal yang paling sering terlewat (jebakan slide): konten repo seperti issue, PR, README, dan
komentar kode adalah **input tidak tepercaya** bagi agen. Instruksi yang ditanam di sana bisa
dibaca agen sebagai perintah (prompt injection tidak langsung). Kontrolnya dipasang bertahap:
deny rule dan sandbox (L2.1), hook agen (L3.1), CODEOWNERS (L3.4), dan pemindai karakter
tersembunyi (L4.3).
