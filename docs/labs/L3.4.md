## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Memasang pemindaian IaC sebagai gerbang CI dan melindungi berkas yang dieksekusi otomatis dengan CODEOWNERS.

1. Jalankan checkov -d infra/; minta Claude memperbaiki dua temuan teratas.
2. Tambahkan job CI yang gagal bila ada temuan high.
3. Buat CODEOWNERS: infra/, Dockerfile, .github/, CLAUDE.md, .claude/.
4. Aktifkan branch protection: wajib review code owner.

**Jebakan umum.** Menekan temuan dengan komentar skip tanpa alasan tertulis.

## Persiapan

- Checkov 3.4.0 (`pip install checkov==3.4.0` di `.venv`, atau image `bridgecrew/checkov:3.4.0`).
- Jadikan `lab/L3.4-start` default branch (CODEOWNERS dibaca dari branch tujuan PR; ruleset
  menarget default branch).
- Butuh tim atau pengguna untuk CODEOWNERS. Di organisasi kelas, buat tim `keamanan` dan `platform`,
  atau ganti dengan `@<username-anda>`.

```bash
git switch lab/L3.4-start && git switch -c kerja/L3.4
```

## Langkah rinci

### Langkah 1 · Jalankan checkov -d infra/; minta Claude memperbaiki dua temuan teratas.

```bash
checkov -d infra/ --framework terraform,kubernetes --compact
```

Temuan yang diharapkan di antara daftar panjang: `CKV_AWS_20` (ACL S3 `public-read`),
`CKV_AWS_24` (SSH dari `0.0.0.0/0`), `CKV_AWS_3` (EBS tidak terenkripsi), dan `CKV_K8S_16`
(kontainer `privileged`).

```text
> Perbaiki dua temuan checkov teratas di infra/main.tf: CKV_AWS_20 (ganti ACL public-read dengan
  aws_s3_bucket_public_access_block yang memblokir semua akses publik) dan CKV_AWS_24 (SSH hanya
  dari variabel admin_cidr). Jangan menambah komentar skip.
```

Lanjutkan sendiri: `encrypted = true` untuk volume, dan `securityContext` non-privileged di
`infra/k8s/deployment.yaml` (`privileged: false`, `allowPrivilegeEscalation: false`,
`runAsNonRoot: true`, `readOnlyRootFilesystem: true`). Jalankan ulang checkov.

### Langkah 2 · Tambahkan job CI yang gagal bila ada temuan high.

Buat `.github/workflows/iac-scan.yml` dengan `bridgecrewio/checkov-action` (dipin SHA), keluaran
`cli,sarif`, unggah SARIF kategori `checkov`.

Checkov open source tidak membawa label severity tanpa API key platform, jadi "gagal bila ada temuan
high" ditulis sebagai daftar check yang disepakati tim:

```yaml
soft_fail: true
hard_fail_on: CKV_AWS_20,CKV_AWS_24,CKV_AWS_3,CKV_K8S_16
```

Temuan lain tetap dilaporkan ke tab Security tanpa memblokir PR.

### Langkah 3 · Buat CODEOWNERS: infra/, Dockerfile, .github/, CLAUDE.md, .claude/.

`.github/CODEOWNERS`:

```text
/CLAUDE.md       @<org>/keamanan
/.claude/        @<org>/keamanan
/.mcp.json       @<org>/keamanan
/.github/        @<org>/platform
/Dockerfile      @<org>/platform
/infra/          @<org>/platform
```

Berkas-berkas ini dieksekusi atau dibaca otomatis (oleh CI, Docker, Terraform, atau agen), jadi
perubahan sekecil apa pun harus dilihat pemiliknya.

### Langkah 4 · Aktifkan branch protection: wajib review code owner.

Terapkan ruleset dari berkas (dijalankan pemilik repo, bukan agen):

```bash
bash scripts/terapkan-ruleset.sh <owner>/kopikita-vuln
```

`.github/rulesets/main-dilindungi.json` mewajibkan PR, 1 approval, **review code owner**, dan
menolak force push serta penghapusan branch default. Atau lewat UI: Settings → Rules → Rulesets.

Uji: buka PR yang hanya mengubah satu baris `CLAUDE.md` (atau berkas di `.claude/`). Tombol merge
terkunci dengan pesan *Review required from code owners*.

## Bukti selesai

- Keluaran `checkov` sebelum/sesudah: empat check di atas berubah dari FAILED menjadi PASSED.
- Workflow **IaC scan** hijau di PR perbaikan, dan **merah** bila salah satu dari empat check dikembalikan.
- PR yang mengubah `CLAUDE.md` terblokir sampai code owner menyetujui.
