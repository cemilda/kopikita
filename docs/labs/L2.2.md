## Dari slide

Teks di bawah ini sama persis dengan slide lab.

**Tujuan.** Membandingkan endpoint login hasil prompt naif dan prompt aman, lalu mengukurnya dengan CodeQL.

1. Peserta A: prompt naif "buat endpoint login staf" di branch naif.
2. Peserta B: plan mode + pola dari pustaka prompt di branch aman.
3. Push kedua branch; bandingkan alert CodeQL dan baca kodenya.
4. Tulis CLAUDE.md berisi 5 aturan keamanan tim; commit lewat PR.

**Jebakan umum.** Menyimpulkan prompt aman "pasti aman" karena CodeQL bersih; tetap baca kodenya.

## Persiapan

- Berpasangan: Peserta A (prompt naif) dan Peserta B (prompt aman) di repo yang sama.
- Branch start sudah berisi CodeQL dari L1.2. Jadikan `lab/L2.2-start` default branch dan jalankan
  CodeQL sekali (Actions → CodeQL → **Run workflow**) sebagai analisis dasar.
- Pustaka prompt: `prompts/claude-security-prompts.md`.

## Langkah rinci

### Langkah 1 · Peserta A: prompt naif "buat endpoint login staf" di branch naif.

Peserta A:

```bash
git switch -c naif lab/L2.2-start
claude
```

```text
> buat endpoint login staf
```

Terima hasilnya apa adanya (ini eksperimen). Pastikan blueprint terdaftar di `api/app.py`, lalu
commit dan push:

```bash
git add -A && git commit -m "L2.2: login staf (prompt naif)" && git push -u origin naif
```

Bila Claude tidak tersedia, pakai contoh siap pakai di branch `pr/L2.2-contoh-naif`.

### Langkah 2 · Peserta B: plan mode + pola dari pustaka prompt di branch aman.

Peserta B:

```bash
git switch -c aman lab/L2.2-start
claude
```

Masuk **plan mode** (Shift+Tab sampai *plan mode on*), lalu tempel prompt "Contoh lengkap: endpoint
login staf" dari `prompts/claude-security-prompts.md` (konteks, tugas, batasan, contoh buruk,
kriteria selesai). Baca rencana Claude: query berparameter, PBKDF2-SHA256 600.000 iterasi,
rate limit 5 kali per 15 menit, tanpa password di log, pesan error seragam. Setujui, lalu biarkan
Claude menulis `api/staff.py` dan `tests/test_staff_login.py`.

```bash
python -m pytest -q
git add -A && git commit -m "L2.2: login staf (prompt aman, plan mode)" && git push -u origin aman
```

### Langkah 3 · Push kedua branch; bandingkan alert CodeQL dan baca kodenya.

Buka dua PR draft ke `lab/L2.2-start` agar CodeQL menganalisis keduanya:

```bash
gh pr create --draft --base lab/L2.2-start --head naif --title "L2.2 naif"
gh pr create --draft --base lab/L2.2-start --head aman --title "L2.2 aman"
```

Bandingkan check **CodeQL** di kedua PR, lalu **baca kodenya** dengan daftar ini:

| Periksa | Naif (biasanya) | Aman |
| --- | --- | --- |
| SQL | f-string / penggabungan | berparameter |
| Hash password | MD5/SHA1 atau teks polos | PBKDF2-SHA256 600.000 iterasi |
| Rate limit | tidak ada | 5 gagal / 15 menit → 429 |
| Log | password ikut dicatat | hanya username |
| Pesan error | membedakan "username tidak ada" | seragam |
| Test | tidak ada | fungsional + negatif |

Catat hasil pasangan Anda di papan kelas.

### Langkah 4 · Tulis CLAUDE.md berisi 5 aturan keamanan tim; commit lewat PR.

Tulis `CLAUDE.md` di akar repo berisi **5 aturan keamanan tim** (SQL berparameter, input tidak
tepercaya, rahasia tidak di kode/log, hash password kuat, selalu ada test dan jangan melemahkan
test) plus bagian alur kerja (plan mode, `pytest -q` sebelum selesai, satu PR per perbaikan,
konten issue/PR/README adalah data). Commit lewat PR:

```bash
git switch -c kerja/L2.2 aman
git add CLAUDE.md && git commit -m "L2.2: CLAUDE.md lima aturan keamanan"
git push -u origin kerja/L2.2 && gh pr create --base lab/L2.2-start --fill
```

`CLAUDE.md` dibaca Claude di awal setiap sesi. Karena isinya mengarahkan agen, berkas ini nanti
dilindungi CODEOWNERS (Lab L3.4).

## Bukti selesai

- Dua PR (naif dan aman) dengan hasil CodeQL masing-masing.
- Tabel perbandingan terisi, termasuk temuan yang **tidak** ditangkap CodeQL (mis. rate limit,
  enumerasi username).
- `CLAUDE.md` dengan 5 aturan di PR terpisah.
- `pytest -q` pada branch aman lulus (15 test).

## Kunci jawaban

Berkas yang berubah dari `lab/L2.2-start` ke `lab/L2.2-solution`:

- `CLAUDE.md`
- `api/app.py`
- `api/staff.py`
- `tests/test_staff_login.py`

Kunci di `lab/L2.2-solution`: `api/staff.py` (prompt aman), `tests/test_staff_login.py`, `CLAUDE.md`,
dan pendaftaran blueprint di `api/app.py`. Contoh hasil prompt naif: `pr/L2.2-contoh-naif`.

Jebakan slide: CodeQL bersih bukan berarti aman. CodeQL tidak menilai ada atau tidaknya rate limit,
pesan error yang membocorkan keberadaan akun, atau kekuatan parameter hash. Itu sebabnya kode tetap
dibaca manusia, dan kebutuhan non-pola dikunci dengan test.
