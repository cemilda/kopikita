## Langkah rinci

### Langkah 1 · Tulis dua aturan Rego: bucket tidak publik, port 22 tertutup.

Conftest mem-parse `.tf` langsung dengan parser HCL2: setiap blok resource menjadi **daftar** objek,
jadi iterasinya `some r in input.resource.<tipe>[nama]`. Tulis `policy/kopikita.rego`:

```rego
package main

import rego.v1

deny contains msg if {
	some name
	some acl in input.resource.aws_s3_bucket_acl[name]
	acl.acl in {"public-read", "public-read-write"}
	msg := sprintf("aws_s3_bucket_acl '%s' memakai ACL %s; bucket tidak boleh publik", [name, acl.acl])
}

deny contains msg if {
	some name
	some sg in input.resource.aws_security_group[name]
	some rule in sg.ingress
	rule.from_port <= 22
	rule.to_port >= 22
	"0.0.0.0/0" in rule.cidr_blocks
	msg := sprintf("aws_security_group '%s' membuka port 22 ke 0.0.0.0/0", [name])
}
```

Lalu test di `policy/kopikita_test.rego` dengan builtin Conftest `parse_config("hcl2", ...)`, supaya
bentuk input test sama persis dengan input asli:

```bash
conftest verify -p policy/
```

### Langkah 2 · Jalankan conftest test pada folder infra/ di CI.

Lokal dulu, termasuk bukti bahwa aturan benar-benar menolak:

```bash
conftest test -p policy/ infra/main.tf                                     # lolos (infra sudah diperbaiki L3.4)
git show main:infra/main.tf > /tmp/rentan.tf && conftest test -p policy/ /tmp/rentan.tf   # 3 FAIL: ACL, SSH, EBS
```

Lalu CI: `.github/workflows/policy.yml` memasang conftest 0.71.1, menjalankan `conftest verify -p policy/`
dan `conftest test -p policy/ infra/main.tf` pada setiap PR yang menyentuh `infra/**` atau `policy/**`.

### Langkah 3 · Susun managed-settings.json: sandbox wajib, domain terkelola.

Susun `managed-settings.json` untuk organisasi kelas:

```json
{
  "permissions": {
    "deny": ["Read(./.env*)", "Read(~/.ssh/**)", "Read(~/.aws/**)"],
    "disableBypassPermissionsMode": "disable"
  },
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "network": {
      "allowManagedDomainsOnly": true,
      "allowedDomains": ["github.com", "pypi.org", "files.pythonhosted.org", "registry.npmjs.org"]
    },
    "credentials": {"files": [{"path": "~/.ssh", "mode": "deny"}, {"path": "~/.aws", "mode": "deny"}]}
  }
}
```

Diskusikan di kelompok: domain mana yang benar-benar dibutuhkan? Apa yang terjadi pada developer
Windows tanpa WSL2 (`failIfUnavailable: true`)?

### Langkah 4 · Uji: matikan sandbox lewat settings proyek; catat pengecualian.

Ikuti uji di `docs/hasil/L4.1-pengecualian.md` (kunci jawaban): pasang managed settings di laptop uji,
ubah `.claude/settings.json` proyek menjadi `"sandbox": {"enabled": false}`, mulai ulang Claude,
jalankan `/sandbox` dan `/permissions`. Sandbox harus tetap aktif karena managed settings menang.

Catat setiap pengecualian yang kelompok butuhkan (mis. `docker` di `excludedCommands`) beserta
alasan, kontrol pengganti, pemilik, dan tanggal tinjau.
