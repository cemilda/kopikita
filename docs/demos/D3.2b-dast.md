### Catatan pembicara

- **Buka.** Tampilkan workflow dast.yml: jalankan aplikasi di runner, lalu pindai.
- **Inti.** Langkah: jalankan aplikasi lab dengan Python di runner CI; jalankan HawkScan dengan stackhawk.yml yang menunjuk ke openapi.yaml dan dua profil login (business logic testing untuk BOLA); gagalkan build bila ada temuan High. Alternatif open source: OWASP ZAP API scan dengan header Authorization dari token login. Temuan diberikan ke Claude untuk menelusuri baris penyebab dan menulis patch beserta test regresi.
- **Persiapan.** StackHawk butuh akun dan API key; siapkan juga jalur ZAP untuk peserta tanpa akun. StackHawk juga menyediakan MCP server agar Claude bisa menjalankan pindai-perbaiki-verifikasi.

## Skrip demo

Branch `lab/L3.2b-solution`; PR uji sudah berjalan sebelum demo (DAST memakan beberapa menit).

1. Buka `.github/workflows/dast.yml`. Sorot sesuai tabel slide: aplikasi dijalankan dengan
   `python api/app.py` di runner; job `zap` (token login → `ZAP_AUTH_HEADER_VALUE`); job `hawkscan`
   hanya bila `HAWK_API_KEY` ada.
2. Buka `stackhawk.yml`: `openApiConf`, login JSON, `tokenExtraction: auth.token`, `testPath`, dua profil,
   `failureThreshold: high`.
3. Lokal, tunjukkan BOLA dengan dua akun (perintah di `docs/labs/L3.2b.md` langkah 1–2):
   token budi membaca `/orders/101` milik alice → 200.
4. Berikan temuan + cURL ke Claude (prompt di `docs/labs/L3.2b.md` langkah 3); tunjukkan baris penyebab
   di `order_detail` dan patch `abort(404)` + `tests/test_bola.py`.
5. Tunjukkan artefak `zap_scan` dan (bila ada akun) hasil HawkScan di dashboard StackHawk.

## Rencana cadangan

- Tanpa akun StackHawk: jalur ZAP saja, dan tegaskan bahwa BOLA dibuktikan dengan uji dua akun.
- Docker tidak tersedia di laptop: tunjukkan run workflow di Actions.
- StackHawk menyediakan MCP server untuk loop pindai-perbaiki-verifikasi dari Claude; cek dokumentasinya
  sebelum kelas bila ingin mendemokannya.
