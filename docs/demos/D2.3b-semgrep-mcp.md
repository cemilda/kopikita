### Catatan pembicara

- **Buka.** Tunjukkan loop temukan-perbaiki-verifikasi tanpa meninggalkan terminal.
- **Inti.** Tambahkan server dengan claude mcp add --scope project semgrep -- uvx semgrep-mcp@0.9.0 (tersimpan di .mcp.json). Izinkan tool-nya di permission allow. Minta Claude: tulis endpoint pencarian produk, lalu jalankan security_check pada berkas yang diubah, perbaiki temuan, dan jalankan ulang sampai bersih. Tunjukkan semgrep_scan_with_custom_rule memakai rule dari L1.2b.
- **Nuansa.** Repo semgrep-mcp yang berdiri sendiri sudah dipindah ke binary semgrep resmi; perintah persis bisa berubah, cek dokumentasi terbaru sebelum kelas.
- **Jebakan.** Server MCP berjalan di luar sandbox Bash; perlakukan sebagai kode pihak ketiga dan pin versinya.

## Skrip demo

Branch `lab/L2.3b-start` di laptop; `uv` terpasang.

1. ```bash
   claude mcp add --scope project semgrep -- uvx semgrep-mcp@0.9.0
   cat .mcp.json
   ```
2. Tambahkan `mcp__semgrep__security_check` (dan `mcp__semgrep__semgrep_scan`) ke `permissions.allow`
   di `.claude/settings.json`. Mulai ulang Claude, setujui server proyek, cek `/mcp`.
3. Prompt dari `docs/labs/L2.3b.md` langkah 2 (endpoint `/search`, loop `security_check` sampai bersih).
   Biarkan peserta melihat satu putaran temuan → perbaikan.
4. ```text
   > Jalankan semgrep_scan_with_custom_rule dengan rule rules/kopikita-sql-taint.yaml pada api/
   ```
   Tool ini tidak ada di allow list, jadi Claude meminta persetujuan: tunjukkan bahwa ini disengaja.
5. Bukti: hasil scan terakhir bersih, `python -m pytest -q` hijau, lalu PR agar CodeQL ikut memeriksa.

## Rencana cadangan

- `uvx` gagal mengunduh paket: tunjukkan `lab/L2.3b-solution` (`api/search.py`, `.mcp.json`) dan jalankan
  `semgrep scan --config rules/ api/` langsung.
- Repo `semgrep-mcp` sudah ditandai deprecated dan server MCP dipindah ke binary `semgrep` resmi.
  Cek dokumentasi Semgrep terbaru sebelum kelas; bila perintah berubah, perbarui juga `.mcp.json`.
