# Demo: rule kustom Semgrep (taint mode)

**Sesi 1.2** · 8 menit · branch `lab/L1.2b-solution` · berkas `rules/kopikita-sql-taint.yaml`

## Dari slide

Teks di bawah ini sama persis dengan slide demo.

| | |
| --- | --- |
| mode | taint |
| pattern-sources | request.args.get(...) · request.form[...] |
| pattern-sanitizers | kopikita.safe_sql(...)  ← sanitizer internal tim |
| pattern-sinks | cursor.execute($Q, ...) |
| Uji | semgrep --test rules/  (contoh ruleid: dan ok:) |
| Dengan Claude | Claude menulis draf rule; test yang membuktikan |

### Catatan pembicara

- **Buka.** Tunjukkan bahwa tim bisa menulis aturan sendiri untuk pola internal yang tidak dikenali scanner bawaan.
- **Inti.** Rule taint Semgrep punya tiga bagian: pattern-sources (data tak tepercaya, mis. request.args), pattern-sanitizers (fungsi pembersih internal tim, mis. kopikita.safe_sql), dan pattern-sinks (fungsi berbahaya, mis. cursor.execute). Mode bawaan menganalisis dalam satu fungsi; versi Pro melacak antar-fungsi dan antar-berkas.
- **Nuansa.** CodeQL juga mendukung query kustom (QL). Semgrep lebih mudah dibaca karena pola menyerupai kode sumber.
- **Latihan.** Minta Claude menulis draf rule dari deskripsi bahasa alami, lalu uji dengan semgrep --test pada contoh benar dan salah. Claude menulis, test yang membuktikan.

## Skrip demo

Di laptop instruktur, branch `lab/L1.2b-start`, `pip install semgrep==1.182.0` sudah dijalankan.

1. Tunjukkan pola internal tim: `api/kopikita/__init__.py` → `safe_sql()` (allowlist kolom).
2. Minta Claude menulis draf rule dari bahasa alami (prompt di `docs/labs/L1.2b.md` langkah 1).
3. Buka hasil di samping `rules/kopikita-sql-taint.yaml` dari `lab/L1.2b-solution`:
   sorot `mode: taint`, tiga source, sanitizer `kopikita.safe_sql(...)`, sink `$CUR.execute($Q, ...)` dengan
   `focus-metavariable: $Q`.
4. Tunjukkan berkas test `rules/kopikita-sql-taint.py`: anotasi `# ruleid:` dan `# ok:`.
5. Jalankan:

   ```bash
   semgrep --test rules/
   semgrep scan --config rules/ api/
   ```

6. Hapus sementara blok `pattern-sanitizers`, jalankan scan lagi: `products` ikut ditandai. Kembalikan.
   Inilah alasan sanitizer internal harus dikodekan.
