### Catatan pembicara

- **Buka.** Push protection menjaga pintu GitHub. Pre-commit hook menjaga lebih awal lagi: di laptop, sebelum commit tercipta.
- **Inti.** Repo lab menyertakan scripts/pre-commit-security.sh (diadaptasi dari Modul 01 repo Secure-Code-AI-Dev) yang memasang framework pre-commit dengan detect-secrets, gitleaks, dan pemeriksa dependensi Python. Tunjukkan commit yang ditolak karena kunci privat.
- **Nuansa.** Pre-commit hook bisa dilewati (git commit --no-verify) dan tidak berjalan untuk developer yang belum memasangnya. Karena itu push protection di server tetap wajib.
- **Persiapan.** Jalankan skrip sekali sebelum kelas agar unduhan hook tidak memakan waktu demo.

## Skrip demo

Branch `main` di laptop instruktur. Skrip sudah dijalankan sekali sebelum kelas (unduhan hook ter-cache).

1. Tampilkan `scripts/pre-commit-security.sh`: hook yang dipasang dan mengapa `pip-audit` di stage manual
   (repo lab sengaja memakai dependensi rentan).
2. ```bash
   bash scripts/pre-commit-security.sh
   cat .pre-commit-config.yaml
   ```
3. Buat kunci privat palsu dan commit:

   ```bash
   printf -- '-----BEGIN OPENSSH PRIVATE KEY-----\nAAAAuji-palsu\n-----END OPENSSH PRIVATE KEY-----\n' > kunci-uji.txt
   git add kunci-uji.txt && git commit -m "uji"        # ditolak
   ```

4. Tunjukkan batasannya: `git commit --no-verify -m "uji"` berhasil. Lalu `git reset --hard HEAD~1`.
   "Lapis 1 di laptop bisa dilewati; lapis 2 di GitHub (push protection) tetap wajib."
5. `pre-commit run pip-audit --hook-stage manual --all-files` untuk melihat advisory dependensi Python.

## Rencana cadangan

- Unduhan hook gagal (jaringan): tampilkan keluaran yang direkam saat persiapan. Hook `detect-private-key`
  bisa diuji tanpa jaringan setelah cache ada.
- Jangan lupa hapus `kunci-uji.txt` dan pastikan tidak ada commit uji yang ter-push.
